# 01 — Marketing landing page audit

Scope: `app/page.tsx`, `components/landing/{LandingPage,LandingNav,sticky-mobile-cta}.tsx`, `components/site-footer.tsx`, `app/globals.css`, `app/responsive.css`, `app/layout.tsx`, `app/opengraph-image.tsx`. I checked the rendered HTML with `curl http://localhost:3000/` (200, 490 KB dev HTML) and probed each linked route. I had no browser, so I judged viewport and fold positions from the CSS values. Criteria come from the frontend-design, better-ui, emil-design-eng and ui-ux-pro-max skills.

## 1. Verdict

**6 / 10 for "feels like a real, funded SaaS".** The page looks the part at a glance: a Linear-style dark layout with detailed product mockups built in HTML/CSS. It loses trust once someone reads it closely. The trust strip calls the company "Solo-built · v0.1". The "Customers" nav link goes nowhere. The page claims integrations that don't exist. The mock data contradicts the product's own HOT/WARM/COLD rules. An investor who judges UI will first notice the self-deprecating trust strip and the missing social proof. If they then click around, they will find the broken and fabricated parts.

## 2. What's already good (keep)

- **The product is shown, not described.** The hero is an HTML mock of the app shell (sidebar, toolbar, filter chips, list, signal-mix bars). It stays sharp at any DPI, and its nav items (Intent Hub, Score, Pipeline, People, Watchlist, Autopilot, Inbox) match real routes in `app/(dashboard)/`. Three more screens follow (score detail, Kanban hub, Autopilot flow). This is the page's strongest asset.
- **The lime is used with restraint.** `#DFFF00` appears on primary CTAs, the score ring and a soft hero glow (`--brand-soft`). It isn't spread across every surface. The hover color is `#E8FF40` as the brand spec requires, and `#D4FF3D` never appears.
- **HOT/WARM/COLD colors are consistent** (`--hot/--warm/--cold`) across the list, hub, people and API mockups.
- **Mobile gets its own preview.** Below 980px the desktop mockup is replaced by a dedicated card (`.hero-mob-preview`) instead of a shrunken screenshot. The sticky mobile CTA respects `env(safe-area-inset-bottom)` and appears only after the hero.
- **The type basics are solid:** one family (Instrument Sans), tight display tracking (`-0.045em`), `text-wrap: balance` on the h1 and `pretty` on the lead, and tabular numbers in the stats.
- **Pricing is clear:** it shows the price per score (`$0.058 each`) and highlights one tier as "Most popular".
- **The API code sample** (`POST /v1/score` with a JSON response) shows the product is built for developers.
- **The accessibility baseline is in place:** a global `prefers-reduced-motion` rule (`globals.css:157`) and global `:focus-visible` styles (`globals.css:147`, `:8713`).

## 4. Top 3 highest-leverage changes (next few days)

1. **A trust and honesty pass (L1, L2, L3, L5, L11, L14). About 2 hours.** Remove "Solo-built · v0.1", the dead Customers link, the fake chevrons, the integrations that don't exist and the filler stats. Label the mockups as illustrative. Each of these can come up in a 20-minute demo. None of them takes design skill to fix, only deletion and rewording.
2. **Make the hero say what the product does and prove it live (L6, L7, L8).** Remove the mascot from the hero. Rewrite the h1 around the outcome ("Know which accounts are about to buy"). Add a one-field "Score a company → stripe.com" demo that returns a real score card from the `MOCK_SIGNALS` path without signup, or open a pre-filled result modal. Keep one announcement. A working product in the first viewport says "funded SaaS" more than any polish can. (M)
3. **One source of truth for the demo data, plus one orchestrated motion (L4, L17).** Render every mockup from a single sorted `DEMO_ACCOUNTS` array with bands computed from the score. Then animate the hero score ring and row stagger once on load. This makes the numbers consistent and gives the page one polished moment of motion. (M)

## 5. Design references for this section

- **Linear (linear.app):** the page already copies its nav, banner and dark app-mockup style. Borrow its one hero load animation and its customer-logo row placed directly under the hero.
- **Clay (clay.com):** the closest competitor in look and feel. The hero shows a live enrichment table, and a strong wall of logos and testimonials follows.
- **Common Room (commonroom.io) and Koala (getkoala.com):** these B2B intent/signal tools show real signal cards ("Visited pricing page", "New funding") as the hero visual. That fits VesperWise's four-trigger story better than a generic app shell.
- **Attio (attio.com):** restrained type, and every section is a product fragment rather than a generic card grid.
- **Resend (resend.com):** shows how to present a developer API with a monospaced code sample and honest early-stage social proof (founder note, GitHub stars).
